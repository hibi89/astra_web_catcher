## 1. 최소한으로 받을 자료

처음에는 **게시물 데이터 1종**만: (a) 개인정보·비밀/토큰을 제외한 **전체 컬럼명** (b) 동일 형식 **5~10행**. CSV 일부 또는 컬럼 목록+샘플 텍스트면 충분하다. 원본 전체 DB/전량 CSV/API 키/접속 주소 필요 없음.

- 계정/게시물 ID는 `B01`/`P001` 등 **샘플 안에서 일관된 가명**으로 치환. 연결키는 5~10행에서 동일 대상에 동일 코드 유지.
- 이름, 이메일, 전화번호, 주소, DM, 사용자 프로필, 실제 access token, signed media URL, 고객/주문 개인 정보 등은 제거. Caption 원문은 불필요; 분석 컬럼만 남기거나 예시값으로 교체.
- `posted_at`의 **시각·타임존 형식**을 가능하면 유지(날짜만 있으면 시간대 차트 불가). NULL, 0, 빈 문자열은 원본 의미를 손실 없이 예시에서 구분. 필드명이 실제 소스에서 어떻게 쓰였는지는 변형하지 않기.
- 브랜드/계정 메타데이터가 게시물과 별도 파일이라면 첫 제출 때 **파일의 컬럼명**만 부연하면 충분. 추가 5~10행은 매핑 필요시 요청.

## 2. 현재 모델 및 매핑할 사용자 컬럼

| 현재 테이블.필드 | 의미와 데이터 타입 | 사용자 측 매핑 대상 | 부재 시 처리(제안·미확정) |
|---|---|---|---|
| `report_runs.id,label,period_start,period_end,created_at,source` | 분석 실행 1회 범위 및 생성시각 | 수집/실행 시간·보고서 기간·배치번호·출처 | 실행단위 메타로 관리; 게시물에서 기간 역산은 반드시 별도 합의 |
| `brands.slug/name` | 브랜드 식별 코드/표시명 | 계정·브랜드 참조키/브랜드명 | 식별 코드가 없으면 조인 불가; 가명/매핑표 요청 |
| `brands.business_type` | 직접 시술 또는 시트형 | 제품·계정 유형/브랜드 분류 | 미확정 분류로 관리; 임의 할당 금지 |
| `brands.follower_count` | 팔로워 수, 0 이상 정수 | 팔로워 수/계정 지표 스냅샷 | 없으면 비교표 일부 공란; 임의 값 생성 금지 |
| `brands.color` | 차트 표시색(디자인용) | 없음 | 별도 UI 기본 색 배정 가능(데이터 분석과 무관) |
| `posts.id,report_id,brand_id` | 게시물 PK/실행 FK/브랜드 FK | 게시물 유일키/실행번호/브랜드 참조 | 안정적인 원본 게시물 키와 중복 판정 정책 확인 필요 |
| `posts.posted_at,hour_kst` | YYYY-MM-DD, KST 시각 0~23 | 게시일시 및 timezone | 날짜만 있으면 시간대 차트 미지원; timezone 불명이면 임의 KST 변환 금지 |
| `posts.medium` | reel/carousel/image | 미디어 유형 | 문자열 매핑표 검토; 낯선 유형은 별도 분류/제외 규칙 협의 |
| `posts.purpose` | 콘텐츠 목적(디자인 소개 등) | LLM 콘텐츠 유형/게시물 목적 | 부재시 콘텐츠 목적 차트 불가, 임의 추론 금지 |
| `posts.treatment` | direct/sheet | 직접 시술·시트형 판정 | 브랜드 기반 추론은 사용자 승인 전 가설 |
| `posts.likes,comments` | 0 이상 정수 | 좋아요·댓글 수 | 수집 불가를 0으로 대체 금지; null 허용 설계 검토 필요 |
| `posts.views` | 정수 또는 NULL | 조회수/재생수 | NULL 그대로 보존(진짜 0과 별도) |
| `posts.analyzed` | 분석 대상 포함 여부 0/1 | is_design_post/품질 판정/포함 플래그 | 미제공 시 포함 기준 합의 필요. 전체를 무조건 분석 대상으로 간주 금지 |
| `posts.url` | 원문 URL(선택) | 게시물 링크(선택) | 샘플에는 제외/가명; 실연동은 권한·안전 URL 필터 추후 결정 |
| `tags.id,name,category` | 태그 사전, 5개 카테고리 | 색/기법/제품/시즌/콘텐츠 분류 컬럼 | 이름 표준화, 복수값 구분자, 신뢰도/미분류 규칙 확인 |
| `post_tags.post_id,tag_id` | 게시물↔태그 다대다 | 레코드별 태그 목록/중간테이블 | 복수 분류인 경우 정규화; source tag vs AI tag 구별 필요 |

현재 정식 `posts` 스키마에서는 likes/comments가 NOT NULL이다. 실제 미수집/비공개값이 존재한다면 **원본 누락을 0으로 변환하지 않고** 추후 별도 staging/스키마 및 집계 정책 변경 승인이 필요하다.

## 3. 현재 집계 규칙 — 원본 공식과 혼동하지 말 것

| 대상 | **현재 MVP의 자체 데모/집계 정의** | 데이터·누락 영향 |
|---|---|---|
| 수집 게시물 | 선택 실행의 전체 `posts` 행 수 | report/brand 조인 필수 |
| 분석 게시물 | `analyzed=1` 건수 | 플래그 의미 사용자 확인 필요 |
| 반응 | `likes + comments` | 둘 중 하나 결측일 때 처리 정책 확정 전 집계 불가 |
| 평균 반응 | 분석 게시물 반응의 산술평균 | 분석 0건 시 NULL |
| 릴스 개수/비중 | 전체 수집 게시물 중 reel 수 / 수집 건수 | 분모 0은 NULL/화면 — |
| 평소 이상 반응 | 분석 게시물 반응 > 각 브랜드 분석 반응 중앙값 | 원본 사이트의 기준은 미확인 |
| 주별 차트 | 분석 게시물, 보고서 period_end를 기준으로 최근 13개 월~일 주간 버킷 | 날짜·보고서 범위·타임존 필요 |
| 시간대별 중앙값 | 분석 게시물 `hour_kst`별 반응 중앙값 | 시각 누락 시 제공 불가 |
| 형식별 반응 | 분석 게시물 `medium+purpose` 그룹 반응 평균 | 두 분류 필드 필요 |
| 유형별 건수 | 분석 게시물 `treatment` direct vs sheet | 판정 기준 필요 |
| 브랜드 반응 중앙값 | 브랜드별 분석 게시물 반응 중앙값 | 필터 선택과 무관하게 4브랜드 비교 |
| 조회수 확보율 | 해당 브랜드 수집 게시물에서 `views IS NOT NULL` 비율 | 조회수 0은 확보됨, NULL은 미확보 |
| 4주 브랜드 지수 | 최근 28일 분석 게시물 반응 중앙값 / 전체 분석 게시물 반응 중앙값 | **데모 공식**, 최근 3건 미만/기준 중앙값 0이면 NULL. 원본 공식 미확인 |
| 태그 수요지수 | 해당 태그의 분석 게시물 반응 중앙값 / 전체 분석 게시물 반응 중앙값 | **데모 공식**, 태그 표본 3건 미만/기준 0이면 NULL |
| 태그 4주÷8주 | 최근 4주 건수/4 ÷ 이전 8주 건수/8 | **데모 공식**, 이전 8주 0건이면 NULL |
| 게시물별 성과지수 | NULL(미구현) | 원본 산식 미확인, 임의 대체 금지 |
| 태그 브랜드 범위 | 현재 MVP는 **전체 브랜드 태그 집계**, 태그 카테고리만 표에 적용 | 원본 세부 상호작용 전체는 미확인, 사용자 데이터 연동 시 별도 결정 |
| 상위 게시물 | 선택 브랜드, `analyzed=1`, 반응 내림차순 상위 20개, 15개씩 페이지, 브랜드 변경시 page=1 | DB 쿼리/정렬과 UI 계약 유지 |

## 4. 실제 자료 수령 후 제공할 분석 산출물 (코드 수정 없음)

1. **컬럼 매핑표**: 실제 컬럼명 → 표준 테이블.필드 / 타입·변환 / 직접·파생·미제공 상태.
2. **누락·품질 매트릭스**: 필수키·브랜드 조인, 시간대, likes/comments와 views NULL/0, analyzed 기준, 카테고리 복수값, 태그 신뢰도, 수집 배치의 누락·중복.
3. **지표 계산표**: 재현 가능한 집계, 공식 미확인, 계산 불가를 표시해 KPI·주간·시간대·브랜드·태그별 사용 가능 범위를 구분.
4. **변경 없는 마이그레이션 계획**: 읽기 전용 원본 → 별도 staging/검증 → 명시적 승인 뒤 개발용 **복제 DB**로 적재. 원본 덮어쓰기·삭제·데모 DB reset 금지.
5. 원본 샘플 5~10행은 전체 13주 트렌드/결측 비율/표준화 품질을 대표하지 않으므로 통계적 품질·운영 적합성 최종 판정에 쓰지 않는다.

**현재 상태:** 사용자 실제 컬럼·샘플 미수령. 본 문서는 현행 구조에 근거한 **매핑 초안**이며 사용자 DB/API 연결·집계 실행·데이터 편집은 **0건**.
