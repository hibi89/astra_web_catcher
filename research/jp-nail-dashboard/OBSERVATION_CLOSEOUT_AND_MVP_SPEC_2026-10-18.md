## 2. 계산 규칙과 데이터 소스 — 정확성 수준

- 유력 후보: 릴스 비중 = 릴스 수 / 수집 게시물 수 * 100, 정수 반올림. 전체 101/194→52%, OHORA 78/94→83%, NAILTOWN 9/61→15%와 일치. 계산 코드 미확인이므로 공식으로 확정 금지.
- 화면 설명 확인: 태그 수요지수 1은 브랜드 평소 수준, 4주/8주는 최근 4주 대 이전 8주 비율. 표본/가중치/집계 단위 불명.
- 확인 못한 항목: 반응의 정확한 정의, 평균/중앙값/성과지수/수요지수 공식, 평소 이상 반응 기준, 시각/주차 구간 처리, 결측/표본 부족 기준.
- API vs 정적 데이터 여부: 미확인. 'n8n 실시간'은 화면 출처 문구이며 실제 네트워크/워크플로 검증 아님.
- 최신 보고서 조회 버튼은 외부 워크플로 실행·비용 가능성이 있어 이 단계에서 미실행. 네트워크 정보가 필요하다면 비밀 제거한 method/path/status/JSON 키만.
- 차트 hover/click, 외부 링크 새 탭, 태그 분류 복귀 상태는 낮은 우선순위 미확인.

## 3. 독립 MVP 재구현 명세 (제안, 원본 스키마 아님)

1. 화면: dashboard / tags / brands / posts, 브랜드·태그 분류·페이지 상태 구분. URL 상태 표현, 오류/로딩/빈 목록 처리.
2. DB: ReportRun(집계시간·기간), Brand(팔로워/구분), Post(게시일/반응/조회수 nullable/콘텐츠 형식), Tag, PostTag, BrandMetricSnapshot, TagMetricSnapshot. 실제 데이터는 DB seed, 프론트 정적 배열 금지.
3. API 후보: GET /api/nails/reports/latest, /api/nails/overview?brand=, /api/nails/tags?category=&page=, /api/nails/brands/compare, /api/nails/posts?brand=&page=&limit=15.
4. 핵심 데이터 흐름: 브랜드 선택 변경 → 대시보드 KPI/차트, 선택 브랜드 Top 20, 오른쪽 상세 패널 갱신; Top 게시물은 페이지 1로 초기화. 브랜드 비교는 4개 브랜드 유지. 태그 분류는 태그 테이블만 변경.
5. 페이지네이션: Top 20을 반응 내림차순으로 15+5 표시, 페이지/필터 상태 일치. SQLite 저장 기준 정확한 필터/정렬/결측 검증. 외부 원문 링크는 가상 URL로 대체.
6. 재구현 지수: 원본 계산식 미확인이므로 자체 검증 가능한 계산식으로 분리하거나 시드의 명시적 집계값 표시. 원본과 동일 산식으로 주장 금지.
7. 테스트: 별도 테스트 DB, API/화면 일치, 브랜드/태그 필터, 비교 화면의 전체 브랜드 유지, Top 20 페이지 2와 브랜드 변경 시 초기화, null/0, 새로고침·서버 재시작 영속성, 가능한 Playwright E2E.

## 4. 구현 경로 비교 및 승인 의존성

| 선택 | 구조 | 장점 | 단점 |
|---|---|---|---|
| A (권고) | 독립 폴더 Next.js + TypeScript + Prisma + SQLite, 별도 브랜치 | 원래 지정한 기술 충족, 타입 검사/빌드/E2E 가능 | npm 패키지 다운로드 가능한 환경 필요, 초기 설정 시간이 더 김 |
| B | FastAPI + SQLite + JS로 새 모듈/화면을 기존 앱과 분리 | 현재 의존성과 테스트 패턴 재사용, 상대적으로 빠름 | 이전에 사용자 승인 없이 기술을 변경한 방식이므로 이번에는 승인 없이 채택 불가 |

권고: A를 기본으로 하고 패키지 설치가 막히면 환경 대안을 찾되 사용자가 동의하기 전 B로 변경하지 않는다. 기존 MVP 원본/데이터는 유지한다.

## 5. 상태

- 네 메뉴 대표 사용자 흐름, 브랜드 변경, 태그 컬러 필터, 브랜드 비교 화면, Top 20 페이지 전환 및 필터 초기화까지 관찰 완료.
- API/DB/n8n 실연동, 모든 원본 공식, 보고서 조회 동작은 미검증으로 남김. 1차 독립 MVP를 위해 원본 동작의 완전한 복원은 필요 없음.
- 다음 단위: 구현 기술안 승인 후 격리된 신규 폴더에서 DB 스키마·seed → API → 핵심 화면 → 독립 자동 테스트. 아직 구현하지 않았음.
