# Astra Web Catcher — 일본 셀프 젤네일 대시보드 관찰·재구현 명세 (1차)

- 대상: https://daily-dashboard-ldh-1013.clevertide128.chatgpt.site/
- 작성일: 2026-10-18 KST
- 범위: **관찰·독립 재구현 명세까지만**. 소스코드/백엔드 수집, 원본 변경, 앱 구현·배포 없음.
- 보존 기준: `hibi89/astra_web_catcher` 기존 `main`의 `/shop`·`/jobs` 및 테스트 변경 금지. 조사 전 `main` HEAD 확인: `dd87ffc847c7b435c7eed7b4543b7db7d184e08c`.
- 관찰 방법: 사용자가 열어 둔 연결 브라우저의 해당 탭에 대한 **읽기 전용 페이지 텍스트** 취득. 동작 클릭·네트워크 캡처·원본 저장소 접근은 수행하지 못함.

## 1. 접근 증거와 한계

| 경로 | 확인 결과 | 해석 |
|---|---|---|
| 웹 조회 | `DisabledError` | 도구의 조회 제한이며 사이트 권한 문제 증거 아님 |
| 컨테이너 HTTPS `requests.get` | `NameResolutionError` (`[Errno -3] Temporary failure in name resolution`) | 이 실행 컨테이너 DNS 실패; 사이트의 접근 정책을 판단할 수 없음 |
| 연결 브라우저 | 탭 제목 **젤네일 인사이트 대시보드**, 요청 URL, 전체 현재 페이지 텍스트 읽기 성공 | 사용자가 열린 페이지의 DOM 텍스트 관찰 성공. 서버 응답 코드/API·클릭 상태는 알 수 없음 |

현재 연결 브라우저 도구는 열려 있는 탭 목록/페이지 내용 읽기만 지원. **마우스 조작을 실시간으로 지켜보거나 버튼을 대신 누르거나 Network 패널을 읽는 기능은 없음.** 사용자가 화면을 조작한 *후* 새 스냅샷을 가져와 비교하는 방법은 가능.

## 3. 확인하지 못한 동작과 계산 규칙

1. 상단 브랜드를 눌렀을 때 어느 KPI·차트·태그·표·우측 인사이트가 함께 바뀌는지, 선택 URL 유지 여부, 합계 재계산/캐시 여부.
2. 왼쪽 메뉴 4개가 페이지 전환, 스크롤 이동, 탭 전환 중 무엇인지; 선택 시 URL/hash 변경 및 검색조건 유지 여부.
3. 태그 유형 버튼이 표만 필터링하는지, 차트/인사이트 전체에 적용되는지, 복수 선택 여부.
4. 브랜드 비교의 비교 단위, 기간 변경 수단, 지수 계산식, 4주÷8주 산정 시 주당 게시물 수 보정 여부.
5. `반응`이 좋아요+댓글인지, 저장·공유 포함인지; `평균 반응`과 `반응 중앙값` 집계 모집단 차이.
6. 조회수 확보율의 분모, 릴스 이외 조회수 결측 처리; 수요지수·성과지수 평소 기준의 기간/브랜드 가중치.
7. `관찰 (표본 부족)` 경계, 수요 높음/낮음 분류 경계, 최대/최소 표본 수 기준.
8. `최신 보고서 조회`의 네트워크 호출, 로딩/오류/갱신 시각 변화, 원본 n8n 워크플로 연동 여부.
9. 실제 API·DB 백엔드 이용인지, 빌드 시 주입한 정적 JSON인지, 브라우저 내 JS 계산인지.
10. 사용자 로그인/권한이 필요한지: 연결 브라우저에 열린 화면만 읽었으며 익명 접속 실험은 실패.

## 4. 독립 DB·API 재구현을 위한 **제안**, 원본의 실제 내부 구조 주장 아님

### 제안 데이터 모델
- `ReportRun`: id, source, executed_at, reporting_start, reporting_end, collected_count, analyzed_count, status, source_version.
- `Brand`: id, display_name, kind, current_follower_count.
- `Post`: id, brand_id, external_permalink, published_at, media_format, content_category, caption_summary(자체 샘플), availability.
- `PostMetricSnapshot`: run_id, post_id, likes, comments, views, engagement_count, engagement_index; **정확한 반응 정의 확정 전까지 파생값 계산 금지**.
- `Tag`: id, name, category (`technique|color|product|season|content`).
- `PostTag`: post_id, tag_id (복수 태그 허용).
- `TagRunMetric`: run_id, brand_scope, tag_id, post_count, demand_index, four_vs_eight_ratio, judgment, formula_version.
- `BrandRunMetric`: run_id, brand_id, analyzed_posts, posts_last4w, median_engagement, index_last4w, view_coverage, follower_snapshot.
- `InsightRunCard`: run_id, card_type, label, value, evidence_query, methodology_version (출력용 요약 생성물).
- `PipelineImport`: run_id, import_batch_id, source_url_or_file, ingested_at, validation_state; 신뢰되지 않는 외부 입력은 검증 후 저장.

모델은 구현 전 사용자의 원본 필드/계산 정의를 검토해 확정. 실제 브랜드/게시물 데이터 무단 크롤링은 계획하지 않음.

### 제안 엔드포인트 (원본 API가 아닌 신규 자체 API)
- `GET /api/reports/latest`: 실행 번호, 집계·기간·수집 상태.
- `GET /api/reports/{runId}/overview?brand=`: KPI와 주별·유형·시간대 차트 데이터.
- `GET /api/reports/{runId}/tags?brand=&category=&sort=&page=`: 필터된 태그와 판정.
- `GET /api/reports/{runId}/brands`: 브랜드별 성과 비교.
- `GET /api/reports/{runId}/posts?brand=&tag=&sort=&limit=20`: 상위 게시물 목록.
- `GET /api/reports/{runId}/insights?brand=`: 우측 인사이트 카드.
- `POST /api/reports/refresh`: **차후 권한 확인과 사용자 승인 후에만** 추가할 내부 수집/갱신 기능. 현재는 버튼 의미 미확인.

### 기능 구현 수락 기준 제안
- 한 `runId` 안에서는 KPI/차트/표/브랜드 합계가 동일 데이터 스냅샷을 바라보고, 새로고침 후에도 같은 결과.
- 브랜드/카테고리/기간 필터는 URL에 반영되고 해당 표/차트가 일관되게 갱신되며 로딩·오류·데이터 없음 구분.
- 공식 계산식 확정 전에는 임의로 `수요지수`/`성과지수`를 만들지 않음. 임시 샘플이면 명확히 샘플 표시.
- 결측 조회수/지수는 `—`로 표시, 0과 결측을 구별.
- 상위 게시물에는 도메인 검사된 출처 링크 사용. 원본 이미지/게시글 콘텐츠 복제하지 않음.
- 사용자별 데이터/인증 요구가 실제로 발견되면 그때 서버 세션 및 권한 검사 설계.

## 5. 사용자에게 필요한 최소 시연 (2~4분 녹화 또는 상태별 스크린샷)

1. **브랜드 필터:** 대시보드 `전체 → OHORA → NAILTOWN → 전체`, 숫자·차트·표 변화가 보이게.
2. **태그 분석:** 왼쪽 `태그 분석` 탭 → `컬러` 및 `디자인 기법` 선택 → 정렬 또는 행 클릭(가능할 때만).
3. **브랜드 비교:** `브랜드 비교` 탭 → 브랜드 카드/그래프 상호작용(가능하면).
4. **상위 게시물:** `상위 게시물` 탭 → 정렬/선택/링크 열림 방식 확인(실제 Instagram 로그인 필요 시 중단).
5. **최신 보고서 조회:** 버튼을 한 번만 클릭해 로딩·오류·시각/집계값의 변화가 보이게. 반복 실행·재수집이 발생할 것 같으면 **누르지 않고** 버튼 설명 화면만 공유.

**API 증빙이 필요해질 경우 (선택):** Chrome DevTools → Network → Fetch/XHR 필터, `Preserve log` 선택 후 버튼 1회 → `Method`/경로(쿼리의 개인키 제거)/상태 코드/응답 JSON의 **필드 이름만** 정리해 전달. HAR 원본·Request Headers·Authorization·Cookie·세션·비밀번호·토큰·개인정보를 보내지 말 것. 본인이 소유한 워크플로/소스/DB라면 민감정보를 지운 설계 문서를 제공하는 편이 가장 정확함.

## 6. 데이터 연결 판정

- 페이지에 n8n 실행 번호, 집계 시각, 기간, 출처 문구가 존재한다는 사실: **확인됨**.
- 그 문구가 실제 서버에서 매번 최신 데이터로 계산된다는 사실: **미확인**.
- 정적 샘플/빌드시 박제한 JSON/서버 API/DB/n8n 중 실제 데이터 출처와 경로: **미확인**.
- Network, 코드, 공식 데이터 설명 없이 `실시간 연동`이라고 판정하지 않을 것.

## 7. 상태

- **작업 결과:** 초기 관찰 보고서 + 독립 재구현을 위한 초안 명세.
- **코드 수정/앱 구현/배포:** 없음.
- **남은 의존성:** 사용자 시연 영상/스크린샷 또는 사용자가 클릭 후 재스냅샷 읽기; 선택적 비밀 제거 Network 근거.
- **완료 판정:** 조사 1차 완료, 상호작용·계산식·데이터 연동은 검증 대기.
