# ASTRA p4 — 7단계 후속 제작 로드맵 / 공수 추정 (2026-10-18)

> **해석 문서, 원설계 아님.** 여기의 진행률·시간·세부 분할은 보조 AI의 **추정 및 제안**이며 사용자 첨부 원문과 구분한다. 최종 목표의 최우선 원문은 [ASTRA_CANONICAL_DESIGN_2026-10-18.md](./ASTRA_CANONICAL_DESIGN_2026-10-18.md). **오호라 프로젝트를 ASTRA의 최종 산출물로 오해하지 말 것**.

## 정의 — 무엇을 만드는가

사용자가 URL과 수동 시연을 제공한다 → 사이트의 **기능·상태변화·사용 흐름**을 관찰하고 근거와 미확인을 기록한다 → **사용자의 데이터 구조/DB/API 계약**과 대응시키고 필요한 변경을 승인받는다 → 지원 기능 범위 내에서 **독립적인 DB/API/프론트**를 생성한다 → **별도 테스트 DB에서 API/UI·회귀 검증**한다 → 기존 프로젝트에 필요한 기능만 통합한다.

**복제의 동일성이나 원본 코드 취득이 목표가 아니다.** 화면 디자인은 적절하게 차별화·변형 가능하고, 기능 구현 방식이 달라도 사용자 작업을 정확하게 수행하는 것이 우선이다.

## 검증된 현재 상태와 완료/미완료 구분

- Step 1: `/shop`, `/jobs` FastAPI/SQLite 데모 구현. 사용자가 주문/지원/재시작 유지 보고. 테스트 13/13, 실제 HTTP 무결성 6/6 PASS 이력. **입력 명세가 있는 경우의 앱 생성 능력 검증**, 범용 URL 분석기 검증은 아님.
- Step 2: 일본 네일 대시보드 4개 메뉴·브랜드/태그 필터·Top20 15+5·리셋 등 사용자 조작+브라우저 DOM 관찰, 근거 문서화. **원본의 실제 서버 코드·DB 구조·API 호출·지표 공식은 확인하지 못함**.
- Step 3: 독립 `nail_dashboard/` 가상 데이터 MVP(33/33 pytest, Windows Playwright 7단계 E2E PASS 사용자 로그), `nail_practice/` 실 CSV 연습(294계정, 1,845게시물, 5,953미디어, 16/16 pytest 및 스크린샷상 Windows UI 렌더 확인). **한 사례의 수작업 중심 재구현과 데이터 연결만 성공**. 공통 생성기로 통합된 상태 아님.
- Step 4: `URL/시연 → 명세 → 코드 → 테스트` **단일 파이프라인 미연결**. 범용 자동화의 가장 큰 공백.
- Step 5~7: **현재 코드 기준 범용 신규 사이트 2~3개 무개입 검증·현업 기존 DB 통합·제한적 실사용 미완료**.
- 추정 종합 진척도 **약 20%**: 검증된 측정치 아님. 원래 7단계 성공 여부를 통과하면 재산정. CSV 대시보드 자체의 90% 등과 섞지 않는다.
